# 邻桥快传（LanBridge）1.0.2.1

邻桥快传是一套面向可信局域网的 Windows 文件传输工具，分为“发送端”和“接收端”两个独立程序。发送端负责选择文件或文件夹、检查连接并发送；接收端负责监听端口、校验数据并把文件保存到指定目录。发布包支持 64 位 Windows 7 SP1、Windows 10 和 Windows 11。

本版统一使用深蓝 / 青色界面，复选框以对勾显示选中；发送端自动扫描在线主机，支持下拉选择和双击自动检测通信，最近连接的 IP / 端口保留 7 天。发布文件与 SHA-256 清单位于 `dist`，实际验证记录见 `docs/1.0.2.1-验证报告.md`。

## 适合谁使用

这套程序适合在同一个家庭、宿舍、实验室或办公室局域网内传送文件。它不依赖云服务器，文件内容直接从发送端传到接收端；日志保存在各自电脑本地。

它的安全边界是“可信局域网”，不是公网网盘或企业级零信任系统。请只在自己管理的网络中运行，并为接收端设置访问码。不要把接收端端口转发到互联网。

## 目标发布文件名

打包发布时建议使用下面的四个文件名：

- `邻桥快传-发送端.exe`：发送端便携版程序。
- `邻桥快传-接收端.exe`：接收端便携版程序。
- `邻桥快传-发送端-安装包.exe`：发送端安装包。
- `邻桥快传-接收端-安装包.exe`：接收端安装包。

发送端和接收端应分别安装或运行；接收文件的电脑运行接收端，发出文件的电脑运行发送端。两端可以安装在同一台电脑上用于自测，也可以安装在两台局域网电脑上实际传输。

## 最快上手

### 1. 在接收电脑上

1. 启动 `邻桥快传-接收端.exe` 或接收端安装包安装后的快捷方式。
2. 确认“保存目录”。第一次启动通常是 `%USERPROFILE%\Downloads\邻桥接收`，可以点击“选择目录”改到其他磁盘。
3. 确认端口。默认是 `53317`；勾选“占用时自动换端口”后，如果该端口已被其他程序占用，程序会依次尝试后面的端口（最多向后尝试 20 个）。
4. 建议在“访问码”中设置一段只在本次局域网使用的密码，然后点击“启动接收”。启动后窗口底部会显示发送端可连接的 IP 和端口。
5. Windows 防火墙第一次拦截时，允许程序在“专用网络”通信。不要为了传输文件而允许“公用网络”或关闭防火墙。

### 2. 在发送电脑上

1. 启动 `邻桥快传-发送端.exe`，程序会自动扫描并弹出在线主机列表。
2. 最近 7 天使用过的 IP / 端口会自动恢复；首次打开按本机 IP 填入，供本机自测。传给另一台电脑时请选择对方。
3. 在列表中双击目标主机，或使用 IP 下拉框选择；IP、端口会自动填写。设置过访问码的接收端需先输入访问码。
4. 选择后自动检测通信，结果显示在连接框左下方。需要时点击“扫描主机”刷新，或手动填 IP 后点击“检测通信”。看到“通信正常”再发送。
5. 在“传输任务”页点击“添加文件”或“添加文件夹”，检查队列中的文件名、相对路径、大小和状态。
6. 点击“开始发送”。队列按顺序发送，发送中可以看到进度和速率；需要停止时点击“取消”。
7. 接收电脑的“接收记录”页会显示文件名、大小、发送端、状态、进度、速度和保存路径。

## 端口与通信检测

程序涉及两个端口：

| 用途 | 默认端口 | 协议 | 是否必须 |
| --- | ---: | --- | --- |
| 文件传输与通信检测 | 53317 | TCP | 必须（可在接收端改） |
| 局域网自动发现 | 53318 | UDP 广播 | 扫描设备时需要；手动填 IP 时可不通 |

“检测通信”不是简单的端口连通测试。它会连接到接收端，完成邻桥协议握手、版本检查和访问码校验，然后由接收端返回 `pong`。因此显示“通信正常”意味着应用层能够正常对话；显示异常时，错误通常比单纯的 `ping` 更有参考价值。

接收端监听 `0.0.0.0`，也就是本机所有 IPv4 网卡。发送端应填写接收电脑在同一局域网中的实际 IPv4 地址，例如 `192.168.1.25`，不要填写发送电脑自己的地址。

## 文件大小、路径和重名规则

- 协议中的文件大小使用无符号 64 位整数，程序没有人为设置的“单文件大小上限”。实际可传大小受磁盘剩余空间、文件系统、网络和 Windows 权限影响。
- 接收端会在开始写入前检查剩余空间。
- FAT32 文件系统无法保存大于约 4 GB 的单个文件，程序会明确记录 `FILESYSTEM_LIMIT`；NTFS 通常更适合大文件。
- 文件以 1 MiB 数据块顺序传输，传输结束后使用 SHA-256 校验。校验失败不会留下最终文件。
- 接收端拒绝绝对路径、`..` 路径和 Windows 保留设备名，并把不适合 Windows 文件名的字符替换为下划线。
- 如果保存目录中已经存在同名文件，程序不会覆盖，而是自动使用 `文件名 (1).扩展名`、`文件名 (2).扩展名` 等新名称。
- 传输中先写入随机名称的 `.lanbridge-*.part` 临时文件；完整接收、刷盘和校验成功后才改名为最终文件。失败时会清理临时文件。

## 访问码与安全边界

访问码为空时，同一网络中能够访问接收端 TCP 端口的设备都可以尝试发送。建议始终设置访问码。

程序不会把接收端访问码明文写入配置文件，而是保存 SHA-256 摘要；每次连接使用随机挑战值和 HMAC-SHA256 完成挑战—响应校验。连续错误访问码会触发按来源 IP 的短时限流。

这仍然不是端到端加密文件传输：当前协议用于可信内网，文件字节本身没有再套 TLS 加密。请注意以下边界：

- 不要把 TCP 53317 或 UDP 53318 映射到公网。
- 不要在不信任的访客 Wi-Fi、公共热点或混合办公网络中无访问码运行。
- 访问码只用于接入控制，不能替代磁盘权限、Windows 账户权限和杀毒软件。
- 日志包含主机名、MAC、IP、端口和文件名，导出日志前应确认没有隐私信息。

## 配置、日志和记录位置

默认数据目录是：

```text
%LOCALAPPDATA%\LanBridge\
├─ settings\
│  ├─ sender.json
│  └─ receiver.json
└─ logs\
   ├─ sender.log
   ├─ receiver.log
   ├─ sender-transfers-YYYY-MM-DD.csv
   ├─ sender-transfers-YYYY-MM-DD.jsonl
   ├─ receiver-transfers-YYYY-MM-DD.csv
   └─ receiver-transfers-YYYY-MM-DD.jsonl
```

“运行日志”页显示的内容也会写入 `sender.log` 或 `receiver.log`。日志文件按大小轮转，保留当前文件和最多 3 个备份。传输记录按日期生成 CSV 和 JSONL 两种格式：CSV 适合 Excel 打开，JSONL 适合程序逐行分析。

每条传输记录包含以下主要字段：

- 时间和状态：`event_time_utc`、`status`、`error_code`、`message`、`transfer_id`。
- 文件信息：`file_name`、`relative_path`、`file_size_bytes`、`bytes_transferred`、`sha256`、`saved_path`。
- 发送端：`sender_hostname`、`sender_mac`、`sender_ip`、`sender_port`。
- 接收端：`receiver_hostname`、`receiver_mac`、`receiver_ip`、`receiver_port`。
- 发送时序和速率：`send_started_at_utc`、`send_completed_at_utc`、`send_duration_seconds`、`send_rate_bytes_per_second`。
- 接收时序和速率：`receive_started_at_utc`、`receive_completed_at_utc`、`receive_duration_seconds`、`receive_rate_bytes_per_second`。
- 版本：`app_version`、`protocol_version`。

传输记录中的时间使用 UTC ISO 8601 格式（末尾通常为 `Z`）；窗口中的运行日志使用本机时间显示。若需要把数据目录放到其他位置，可在启动程序前设置环境变量 `LANBRIDGE_DATA_DIR`，例如：

```powershell
$env:LANBRIDGE_DATA_DIR = 'D:\LanBridgeData'
```

## Windows 防火墙和 SmartScreen

首次启动接收端时，Windows 可能弹出“Windows Defender 防火墙已阻止此应用的部分功能”。只在确认程序来自本项目、且当前网络是“专用网络”时允许访问。若此前点了“取消”，可在“Windows 安全中心 → 防火墙和网络保护 → 允许应用通过防火墙”中重新勾选专用网络。

如果安装包或 EXE 没有代码签名，Windows SmartScreen 可能显示“Windows 已保护你的电脑”。这不是传输协议报错，而是发布者证书缺失的提示。请先核对文件来源和 SHA-256，再点击“更多信息 → 仍要运行”；正式分发时应使用可信代码签名证书。不要为了绕过提示而关闭 SmartScreen。

## 常见问题

### 扫描不到接收端

扫描结合 UDP 接收端发现、TCP / ICMP 存活检测及主机名查询，默认约 4 秒，最多探测 512 个地址。按真实网卡掩码扫描；大于 /24 的网络仅探测本机附近 /24 与同网段缓存邻居。“主机在线”不等于接收服务可用，最终以通信检测为准。主机未公开名称时显示“未知主机”。Wi-Fi AP 隔离、访客网络、VPN 或防火墙都可能造成漏检，可从接收端窗口复制 IPv4 地址，手动填写 IP 和 TCP 端口后检测。

### 显示“连接被拒绝”

通常表示接收端没有运行、端口填错，或接收端自动换了端口。请以接收端窗口当前显示的端口为准；如果接收端勾选了自动换端口，不能继续使用旧端口。

### 显示“连接超时”

检查两台电脑是否在同一局域网、Windows 网络配置是否为“专用网络”、防火墙是否允许 TCP 53317（或当前实际端口），以及是否连着会隔离客户端的访客 Wi-Fi。也要确认填写的是接收电脑 IP，而不是路由器地址。

### 显示“访问码错误”

访问码必须与接收端当前保存的访问码完全一致。接收端运行中不能直接修改访问码：先点击“停止”，输入新访问码后再次启动；发送端也要同步修改。连续输错多次后可能暂时限流，请等待约 1 分钟再试。

### 文件发送成功但找不到

在接收端点击“打开接收目录”，或查看接收记录的“保存路径”。同名文件会自动加 `(1)`、`(2)`，不会覆盖原文件。

### 大文件失败

检查接收盘剩余空间和文件系统。FAT32 不支持超过约 4 GB 的单文件；可改用 NTFS 或 exFAT。不要在传输过程中移动、重命名或修改发送端源文件，否则程序会以 `SOURCE_CHANGED` 拒绝提交。

### 程序关闭时提示仍有任务

这是保护提示。发送端或接收端会先询问是否确认退出；确认后当前连接会被关闭，未完成文件不会被当作成功文件保留。

## 从源码启动（给维护者）

从源码启动需要 Python 3.8 或更高版本，并让项目根目录位于模块搜索路径中。Windows PowerShell 示例：

```powershell
$env:PYTHONPATH = "$PWD\src"
python .\receiver.py
python .\sender.py
```

`--smoke-test` 参数只用于自动打开窗口后短暂退出的冒烟检查，不代表已经完成完整的双机传输测试。

## Windows 打包（给维护者）

兼容 Windows 7 SP1 的发布包必须在 Windows x64 上使用 64 位 Python 3.8.10 构建。3.8.10 是最后一个官方提供 Windows 安装程序且支持 Windows 7 的 CPython 版本；脚本会拒绝 Python 3.9 及更高版本，防止误生成只能在 Windows 10/11 运行的包。还需要 Inno Setup 6。构建脚本会删除同名旧产物，生成图标、两个独立 EXE 与两个独立安装包，并自动执行 PE、内置运行时、SHA-256、便携启动、静默安装启动和卸载检查：

```powershell
& .\scripts\build_windows.ps1 -Python $py -InstallDependencies
```

如果只需要生成便携版 EXE，使用 `-SkipInstallers`。发布 EXE 已内置 Python 3.8、Tcl/Tk 和程序依赖，目标电脑无需安装 Python，也无需联网下载环境。最低系统版本是 64 位 Windows 7 SP1；未安装 SP1 的 Windows 7、32 位 Windows 和 Windows XP 不受支持。脚本不会签名文件，正式分发时应使用代码签名证书；没有证书时 Windows SmartScreen 可能显示“未知发布者”。
