# 邻桥快传技术设计概述

## 1. 项目目标

邻桥快传（LanBridge）是一个面向 Windows 可信局域网的点对点文件传输系统。系统拆分为发送端和接收端两个 GUI 应用，目标是让非技术用户通过 IP、端口和访问码完成文件传输，并在传输记录中保留可追溯的主机、网络、文件和时间信息。

本说明只描述当前源码中的设计，不把尚未执行的构建、双机压测或安装包验收写成既成事实。项目中的“测试结果”应以实际运行记录、截图和测试表为准。

## 2. 总体架构

系统采用分层、双进程结构：

```text
发送端 GUI（Tkinter）
        │
        ├─ SenderService：队列、连接、分块读取、进度、发送日志
        ├─ Protocol：帧编码、握手、挑战响应、错误消息
        └─ TransferLogger / ActivityLogger：CSV、JSONL、运行日志
                 │ TCP 文件传输 / 通信检测
                 ▼
接收端 GUI（Tkinter）
        │
        ├─ ReceiverServer：监听、并发控制、接收、落盘、校验
        ├─ DiscoveryResponder：UDP 53318 局域网发现
        └─ 路径安全、重名处理、临时文件、接收日志
```

公共模块负责常量、路径、身份信息、端口校验、文件名清理和日志模式。发送端与接收端没有中心服务器，文件字节直接在两台电脑之间传输。

## 3. 网络端口与发现机制

- TCP `53317` 是默认传输端口，同时承载应用层通信检测。
- UDP `53318` 是默认发现端口。接收端绑定 `0.0.0.0`，收到带有 `LQDISC1 ` 标识的 `discover` 广播后，返回主机名、MAC、传输端口、应用版本、协议版本和是否需要访问码。
- 发送端扫描时向 `255.255.255.255`、实际网卡子网广播地址和 `127.0.0.1` 发送发现请求；`lan_scan.py` 补充 TCP / ICMP 存活探测和 NetBIOS / 反向 DNS 主机名查询。扫描在后台运行，默认 4 秒，最多 512 个地址、32 个探测线程及全局最多 8 个主机名查询线程，关窗可取消。未知主机名如实显示；通用在线状态不替代应用层验证。
- 接收端指定端口被占用且启用自动换端口时，会从起始端口向后尝试最多 20 个端口；实际端口显示在 GUI 和发现响应中。

发现协议仅用于列出设备，不承载文件内容，也不代替 TCP 应用层检测。

## 4. 应用层协议

TCP 控制消息采用固定头加 JSON 体的帧格式：

```text
4 字节 magic（LQFT）
1 字节协议版本
4 字节网络字节序 body 长度
JSON 控制消息
```

控制帧大小限制为 64 KiB，文件数据不放入 JSON，而是在 `ready` 控制帧之后直接传输。主要消息序列如下：

1. 发送端发送 `hello`，携带 `action`（`probe` 或 `transfer`）、会话号、发送端身份和文件 offer。
2. 接收端返回随机 32 字节 `challenge`，并声明是否需要访问码。
3. 发送端返回 `auth`。设置访问码时，摘要为基于访问码派生密钥的 HMAC-SHA256；未设置访问码时为空摘要。
4. `probe` 操作收到 `pong` 后结束；`transfer` 操作在校验文件路径、大小、磁盘空间和文件系统后返回 `ready`。
5. 发送端按 1 MiB 块读取源文件并通过 TCP `sendall` 发送，同时计算 SHA-256 和发送速率。
6. 数据发送完毕后，发送端发送 `finish`，包含摘要、发送字节数、源文件是否变化、发送开始/结束时间和速率。
7. 接收端比较摘要和字节数，成功后将 `.part` 文件原子替换为最终文件并返回 `complete`；失败则返回带错误码的 `error`，并清理临时文件。

协议版本当前为 `1`，魔数或版本不匹配会被拒绝，避免把普通服务端口误当成邻桥服务。

## 5. 文件安全与可靠性设计

### 5.1 路径安全

接收端只接受相对路径，拒绝绝对路径、盘符路径、空路径和 `..` 路径；文件名中的 Windows 非法字符会被替换，保留设备名会加前缀。最终路径通过 `resolve` 和 `commonpath` 检查，确保仍在接收根目录内。

### 5.2 临时文件与原子提交

接收端先通过 `NamedTemporaryFile` 独占创建随机名称的 `.lanbridge-*.part` 文件，写完后执行 flush 和 `fsync`，Windows 使用不覆盖目标的 `os.rename` 提交最终文件。异常、超时、服务停止、校验失败或连接中断时删除临时文件，避免把半个文件伪装成成功结果。

### 5.3 完整性校验

发送端和接收端对相同的文件字节流计算 SHA-256。接收端同时验证 `bytes_sent` 与实际收到的字节数，并检查发送过程中源文件的大小和修改时间是否发生变化。任一条件不满足，传输记为失败。

### 5.4 空间、文件系统和重名

接收开始前检查目标磁盘剩余空间；在 Windows FAT/FAT32 上拒绝超过约 4 GB 的单文件。目标存在或被并发任务预留时，使用 `(1)`、`(2)` 等候选名，不覆盖旧文件。当前接收服务最多同时处理 4 个连接，超出时返回 `BUSY`。

### 5.5 超时、取消和限流

连接建立默认超时为 5 秒，I/O 默认超时为 30 秒。发送端通过线程事件取消队列；接收端停止服务时关闭监听器和现有连接。访问码错误按来源 IP 记录，1 分钟内累计达到 5 次后暂时拒绝继续尝试。

## 6. 访问控制边界

访问码不以明文写入接收端设置文件，而是保存 SHA-256 摘要。每次连接的随机 nonce 与握手文档参与 HMAC-SHA256，减少重放同一摘要的风险。

该设计提供的是可信局域网接入控制，不是完整的端到端加密。文件数据在 TCP 连接中未使用 TLS 加密，因此系统不应部署到公网，也不应依赖访问码替代防火墙、账户权限和磁盘权限。项目说明应把“可信局域网”写为明确的威胁模型和适用范围。

## 7. 日志与可追溯性

每个角色有一个 `ActivityLogger` 记录人类可读的运行事件，并以滚动文件保存；`TransferLogger` 每次传输写入 CSV 和 JSONL。传输记录覆盖：

- 传输会话、文件名、相对路径、文件大小、已传字节数、SHA-256；
- 发送端和接收端主机名、MAC、IP、端口；
- 发送和接收的开始时间、结束时间、耗时、平均速率；
- 成功/失败/取消状态、错误码、错误消息、保存路径、应用版本和协议版本。

日志目录默认为 `%LOCALAPPDATA%\LanBridge\logs`，设置目录为 `%LOCALAPPDATA%\LanBridge\settings`。传输时间以 UTC ISO 8601 保存，便于两台电脑合并分析。

## 8. GUI 交互设计

发送端采用“连接区 + 传输任务/运行日志页签 + 底部队列操作”的布局，核心操作顺序是：扫描或填写地址 → 检测通信 → 添加文件/文件夹 → 开始发送。接收端采用“接收服务设置区 + 接收记录/运行日志页签 + 底部目录入口”的布局，核心操作顺序是：选择目录和端口 → 设置访问码 → 启动接收 → 查看记录。

两端都显示主机名、MAC 或 IP 等身份信息，并把后台线程事件通过队列回送 GUI 主线程，避免网络 I/O 阻塞界面。发送队列按顺序执行，接收端可并发处理有限数量连接。

## 10. 已知限制和后续改进方向

- 当前协议面向 IPv4，尚未提供 IPv6 专门界面。
- 文件内容未使用 TLS 加密；若部署到不完全可信网络，应增加 TLS 或基于 Windows 凭据的认证。
- 自动发现依赖 UDP 广播，跨网段路由和客户端隔离环境需要手动填写 IP。
- 当前队列发送为单发送端顺序处理；可在后续版本中讨论断点续传、暂停/恢复、带宽限制和更细粒度的并发调度。
- 安装包若未配置代码签名，Windows SmartScreen 会显示未识别发布者提示；正式发布应增加签名、版本升级和卸载清理策略。

## 11. 建议的发布物

毕业设计演示时可按角色分别提供：

```text
邻桥快传-发送端.exe
邻桥快传-接收端.exe
邻桥快传-发送端-安装包.exe
邻桥快传-接收端-安装包.exe
```

其中 EXE 是便携运行文件，Setup 是带快捷方式和卸载入口的安装包。发布说明或答辩材料应注明每个文件的实际生成时间、文件大小、SHA-256 和是否已代码签名；如果某项尚未完成，应明确写“待打包/待签名”，不要虚构验收结果。
