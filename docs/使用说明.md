# 邻桥快传 1.0.2.1 使用说明

本说明写给不熟悉代码的使用者。只要按“接收端先启动、发送端后连接”的顺序操作，就可以在同一局域网内传送文件。

## 一、先认识两个程序

| 程序 | 在哪台电脑运行 | 主要作用 |
| --- | --- | --- |
| 邻桥快传·接收端 | 保存文件的电脑 | 选择保存目录、监听端口、接收并校验文件 |
| 邻桥快传·发送端 | 发出文件的电脑 | 选择文件、填写接收地址、检查通信、发送文件 |

建议把接收端电脑称为“B 电脑”，发送端电脑称为“A 电脑”。A、B 必须连接到同一个可以互相访问的局域网。两台电脑可以使用 64 位 Windows 7 SP1、Windows 10 或 Windows 11；Windows 7 必须已经安装 SP1。不要把“同一个 Wi-Fi 名称”简单等同于“一定互通”，访客 Wi-Fi 可能会隔离客户端。

## 二、接收端设置（B 电脑）

### 1. 选择保存目录

打开接收端，顶部会显示本机主机名和版本号。设置面板中的“保存目录”是最终文件保存位置，默认值为：

```text
%USERPROFILE%\Downloads\邻桥接收
```

可以直接填写路径，也可以点击“选择目录”。程序会自动创建不存在的目录。建议选择空间充足、文件系统为 NTFS 或 exFAT 的磁盘。

### 2. 设置端口

默认传输端口为 TCP `53317`。如果这个端口被占用，可以：

1. 勾选“占用时自动换端口”，让程序从填写的端口开始向后寻找可用端口；或
2. 手动改成 `1024` 到 `65535` 之间的其他端口。

接收端启动后，窗口底部会列出类似下面的地址：

```text
发送端可连接：192.168.1.25:53317
```

发送端要使用这里显示的当前端口，而不是凭记忆填写默认端口。如果端口发生自动切换，以界面当前显示值为准。

### 3. 设置访问码

“访问码”是发送端连接接收端时的共享密码。建议使用至少 8 位、只在当前局域网使用的密码。设置后点击“启动接收”，输入框会清空，但旁边会显示“已保存访问码；留空会继续使用”。这表示访问码摘要已经保存，并不表示访问码丢失。

要更换访问码：

1. 点击“停止”；
2. 在访问码框输入新密码并重新点击“启动接收”；
3. 在发送端同步填写新密码。

如果要取消访问码，停止接收后点击“清除访问码”，再启动服务。取消访问码会让任何能访问 TCP 端口的局域网设备都可以尝试连接，不建议在陌生网络使用。

### 4. 启动和停止

默认会在程序启动后自动监听。也可以取消“下次启动时自动监听”，改为每次手动点击“启动接收”。服务运行时配置控件会暂时锁定，避免传输途中改变端口、目录或访问码。

## 三、发送端设置（A 电脑）

### 1. 填写地址

在“接收端连接”区域填写：

- **IP 地址**：B 电脑显示的局域网 IPv4，例如 `192.168.1.25`；
- **端口**：B 电脑当前监听的 TCP 端口，例如 `53317`；
- **访问码**：B 电脑设置的访问码；没有访问码时留空。

发送端打开约半秒后会自动扫描，并弹出主机列表。列表显示主机名、IP、端口、在线状态与访问码提示，双击一行即可自动填写并检测通信。IP 输入框也是可编辑的下拉菜单，可以选择已发现的主机，或手动输入地址；“扫描主机”按钮可重新扫描。

首次启动按本机 IP 自动填写，仅用于同一电脑自测；向 B 电脑发送时应选择 B 电脑。最近使用的 IP 和端口保留 7 天，成功检测、传输或退出时保存；重开后自动恢复，扫描结果不会擅自覆盖地址。访问码不会保存在发送端。

“主机在线”仅表示探测收到响应，目标可能是路由器或没有运行接收端的电脑；“接收端在线”表示发现了邻桥服务，仍需通过通信检测。设备没有公开主机名时显示“未知主机”。扫描约 4 秒、最多探测 512 个地址；大网段仅扫描本机附近 /24 和同网段缓存邻居。防火墙或网络隔离可能导致漏检，扫描不到时仍可手填 IP 和端口。

### 2. 检测通信

双击主机或从下拉框选中后会自动检测；若目标需要访问码，会提示先填写再点击“检测通信”。结果位于连接框左下方。程序会进行一次真实的应用层握手：

1. 连接 TCP 端口；
2. 检查邻桥协议标识和协议版本；
3. 完成访问码挑战—响应；
4. 等待接收端返回通信确认。

只有看到绿色的“通信正常”后才建议开始发送。检测失败时，先根据界面提示排查 IP、端口、访问码和防火墙。

### 3. 添加文件或文件夹

切换到“传输任务”页：

- 点击“添加文件”可一次选择多个文件；
- 点击“添加文件夹”会递归扫描文件夹内的文件，并保留文件夹相对路径；
- 选中任务后点击“移除所选”；
- 点击“清空队列”删除尚未发送的任务。

队列表格中的“文件名、发送路径、大小、状态、进度、速度”都是本地显示。程序按队列顺序逐个发送，不会因为列表中有很多文件而同时占满网络。

### 4. 开始发送和取消

点击“开始发送”后，连接信息和队列按钮会暂时锁定。成功的文件显示“成功”，失败的文件显示“失败”，其他文件仍按顺序继续尝试。点击“取消”会停止当前队列；已完成的文件不会被删除，未完成文件不会被标记为成功。

## 四、接收端查看结果

接收端的“接收记录”页显示本次运行中的：

- 开始时间；
- 文件名和大小；
- 发送端 IP；
- 接收状态；
- 进度和接收速率；
- 最终保存路径。

成功后点击“打开接收目录”即可查看文件。相同文件名不会覆盖旧文件，程序会自动生成 `(1)`、`(2)` 后缀。

## 五、日志在哪里

点击两个程序底部或“运行日志”页中的“打开日志目录”，会打开：

```text
%LOCALAPPDATA%\LanBridge\logs
```

主要文件如下：

| 文件 | 内容 |
| --- | --- |
| `sender.log` | 发送端启动、扫描、通信检测、发送成功/失败等运行消息 |
| `receiver.log` | 接收端启动、监听、访问码错误、接收成功/失败等运行消息 |
| `sender-transfers-YYYY-MM-DD.csv` | 发送端每日传输明细，可用 Excel 打开 |
| `receiver-transfers-YYYY-MM-DD.csv` | 接收端每日传输明细，可用 Excel 打开 |
| 对应 `.jsonl` 文件 | 同一批记录的逐行 JSON 格式，适合进一步分析 |

传输明细会记录：文件名、文件大小、传输时间、发送/接收开始和结束时间、发送/接收耗时、发送/接收速率、发送端和接收端主机名、MAC、IP、端口、SHA-256、最终路径、状态和错误码。

时间字段以 UTC 保存；运行日志窗口按本机时间显示。日志只保存在本机，程序不会把日志上传到服务器。

## 六、Windows 防火墙操作

第一次启动接收端时，如果弹出防火墙提示：

1. 确认程序名称是邻桥快传；
2. 只勾选“专用网络”；
3. 点击“允许访问”。

若错过提示，可打开“Windows 安全中心 → 防火墙和网络保护 → 允许应用通过防火墙”，为接收端勾选专用网络。自动发现还需要允许 UDP `53318`；手动填写 IP 时，至少要允许接收端当前 TCP 端口。

不要为了让程序工作而关闭 Windows 防火墙，也不要把网络改成“公用网络”后长期运行。

## 七、SmartScreen 提示

如果使用的是未签名的自行打包版本，Windows 可能显示“Windows 已保护你的电脑”。请：

1. 核对 EXE 或安装包来源；
2. 如发布方提供 SHA-256，先进行校验；
3. 确认无误后点击“更多信息 → 仍要运行”。

这只是代码签名信誉提示，不等同于程序运行失败。正式对外发布时应为安装包和 EXE 配置可信代码签名证书。不要通过关闭 SmartScreen 来解决问题。

## 八、常见故障排查表

| 现象 | 优先检查 |
| --- | --- |
| 扫描不到设备 | 两台电脑是否同一网段；是否允许 UDP 53318；是否为访客 Wi-Fi；接收端是否已启动 |
| 连接被拒绝 | 接收端是否运行；端口是否为当前实际端口；是否填错电脑 IP |
| 连接超时 | TCP 防火墙规则、专用网络、Wi-Fi 客户端隔离、VPN/虚拟网卡 |
| 访问码错误 | 两端密码是否完全一致；接收端是否刚更换过密码；是否触发短时限流 |
| 接收目录没有文件 | 查看接收记录保存路径；检查是否自动加了 `(1)`；查看 CSV/JSONL 错误码 |
| 大文件失败 | 接收盘剩余空间、NTFS/exFAT 文件系统、发送过程中源文件是否被修改 |
| 端口无法启动 | 关闭占用该端口的程序，或启用“占用时自动换端口” |

### 用 PowerShell 做基础端口检查

在发送端可以执行下面的命令检查 TCP 端口是否可达（把地址和端口替换成接收端当前值）：

```powershell
Test-NetConnection 192.168.1.25 -Port 53317
```

显示 `TcpTestSucceeded : True` 只能说明 TCP 端口可连接；仍应回到发送端点击“检测通信”，因为只有应用层检测会验证协议和访问码。

## 九、文件大小和安全提示

程序没有人为的单文件大小上限，文件大小使用 64 位数值记录。但实际限制仍来自接收磁盘剩余空间、文件系统和操作系统权限。FAT32 无法保存大于约 4 GB 的单文件。

程序会拒绝危险路径，不会覆盖同名文件，传输过程中使用 `.part` 临时文件，完成 SHA-256 校验后才提交最终文件。访问码用于局域网接入控制；文件内容本身不是 TLS 加密，因此只应在可信局域网使用。

## 十、发布文件名和源码启动

建议的发布文件名：

```text
邻桥快传-发送端.exe
邻桥快传-接收端.exe
邻桥快传-发送端-安装包.exe
邻桥快传-接收端-安装包.exe
```

如果暂时没有安装包，也可以使用便携版 EXE。开发或维护者从源码启动时，可在项目根目录执行：

```powershell
$env:PYTHONPATH = "$PWD\src"
python .\receiver.py
python .\sender.py
```

`--smoke-test` 只用于快速打开窗口并自动退出的冒烟检查，不是完整的双机传输验收。
